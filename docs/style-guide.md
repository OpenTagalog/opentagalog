# OpenTagalog Style Guide

This document defines the writing and content standards for all educational material within **OpenTagalog**.

Following this guide ensures that every lesson, dictionary entry, and grammar explanation provides learners with a consistent, professional, and enjoyable learning experience.

---

# Guiding Principles

OpenTagalog should always be:

- Clear
- Friendly
- Accurate
- Practical
- Beginner-friendly
- Consistent
- Accessible
- Community-driven

When writing educational content, always assume that the learner has little or no previous knowledge of Tagalog.

---

# Educational First

OpenTagalog prioritizes educational value over linguistic completeness.

Whenever there is a choice between a technically perfect explanation and one that is easier for learners to understand, prefer the explanation that best supports learning while remaining factually correct.

More advanced or nuanced details should be introduced gradually in later lessons or within the Grammar Reference rather than overwhelming beginners.

The goal is to build confidence through steady progress.

---

# Language

All explanations should be written in clear English.

Avoid unnecessary linguistic terminology whenever a simpler explanation is sufficient.

Prefer:

> "This word means..."

instead of

> "This lexical item represents..."

The goal is to teach, not to impress.

---

# Tone

Use a friendly, encouraging, and respectful tone.

Avoid:

- sarcasm
- slang
- political opinions
- offensive language
- controversial examples

Lessons should remain appropriate for learners of all ages.

---

# Lesson Structure

Every lesson should follow the project lesson template.

A typical lesson contains:

1. Introduction
2. Vocabulary
3. Pronunciation
4. Examples
5. Grammar Notes (if applicable)
6. Exercises
7. Quiz
8. Summary

Not every lesson requires every section, but the overall structure should remain familiar.

---

# Vocabulary

Vocabulary should always include:

- English
- Tagalog
- Pronunciation

Example:

| English | Tagalog | Pronunciation |
|----------|----------|---------------|
| Hello | Kumusta | koo-moos-TAH |

Introduce vocabulary gradually.

Avoid introducing large numbers of unfamiliar words in a single lesson.

Whenever possible, new vocabulary should reuse words already introduced in previous lessons.

---

# Pronunciation

Use simple English pronunciation guides.

Do not use the International Phonetic Alphabet (IPA) in beginner lessons.

Preferred:

```
koo-moos-TAH
```

instead of

```
/kʊmusˈta/
```

IPA may be included in advanced dictionary or grammar reference pages.

---

# Example Sentences

Examples should:

- sound natural
- be useful in everyday situations
- use previously learned vocabulary whenever possible
- avoid unnecessary complexity

Always include an English translation.

Example:

Tagalog:

```
Magandang umaga po.
```

English:

```
Good morning.
```

---

# Grammar

Introduce grammar gradually.

Explain one concept at a time.

Avoid long grammar explanations in beginner lessons.

Allow learners to encounter grammar naturally before studying it in depth.

Detailed explanations belong in the Grammar Reference.

---

# Quizzes

Quizzes should reinforce the lesson.

Prefer practical questions over memorization.

Examples:

- What does "Salamat" mean?
- How do you say "Good morning" in Tagalog?
- Which greeting would you use in the evening?

Avoid trick questions.

---

# Audio

Whenever available:

- Vocabulary should include pronunciation audio.
- Example sentences should include pronunciation audio.

Native speaker recordings are preferred.

Browser Text-to-Speech (TTS) may be used until native recordings become available.

---

# Dictionary Links

Whenever possible:

- vocabulary should link to its dictionary entry
- grammar topics should link to the Grammar Reference

Avoid duplicating explanations throughout the course.

---

# Formatting

Use Markdown headings consistently.

Prefer:

```markdown
## Vocabulary
```

instead of:

```markdown
### VOCABULARY ###
```

Use:

- tables for vocabulary
- bullet lists for short lists
- numbered lists for sequences

Avoid excessive bold or italic formatting.

---

# Accessibility

Educational content should be accessible.

Please:

- use descriptive headings
- provide alt text for images
- use meaningful button labels
- ensure keyboard accessibility
- avoid relying solely on color
- keep paragraphs reasonably short

---

# Cultural Notes

When cultural explanations are included:

- remain factual
- avoid stereotypes
- explain context
- acknowledge regional variation where appropriate

---

# Native Speaker Review

Whenever possible, educational content should be reviewed by a fluent or native Tagalog speaker before being considered complete.

This is especially important for:

- example sentences
- idioms
- pronunciation guidance
- cultural explanations

Community corrections are always welcome.

---

# Consistency

Throughout the project:

- use consistent terminology
- use the same pronunciation style
- use the same lesson structure
- avoid duplicate explanations
- prefer reusable components over repeated content

---

# Writing Philosophy

OpenTagalog teaches practical Tagalog that learners can immediately use in everyday life.

Whenever possible:

- show before explaining
- use examples before definitions
- encourage practice
- make learning enjoyable
- build confidence one lesson at a time

---

# Terminology

To maintain consistency throughout OpenTagalog, contributors should use the following terminology whenever applicable.

## Language

Use **Tagalog** when referring to the language taught in this project.

Use **Filipino** only when specifically discussing the national language of the Philippines or explaining the relationship between Filipino and Tagalog.

---

## Course Structure

Use these terms consistently:

| Preferred | Avoid |
|-----------|-------|
| Course | Tutorial |
| Lesson | Chapter |
| Unit | Section (when referring to groups of lessons) |
| Vocabulary | Word List |
| Grammar Reference | Grammar Guide |
| Dictionary | Word Database |

---

## Lesson Components

Always use the official component names.

- Vocabulary Card
- Audio Button
- Grammar Box
- Culture Note
- Example Sentence
- Flashcard
- Quiz

Avoid inventing alternative names for the same component.

---

## Grammar Terminology

Use the same grammatical terminology throughout the project.

Examples include:

- Actor Focus
- Object Focus
- Location Focus
- Benefactive Focus
- Instrument Focus

If an alternative term exists, introduce it once and continue using the preferred project terminology.

---

## Pronunciation

Use simple English pronunciation guides throughout the course.

Example:

```
koo-moos-TAH
```

IPA should only appear in advanced reference material.

---

## English Style

OpenTagalog follows **American English**.

Examples:

- color
- favorite
- center
- traveled

Avoid mixing American and British spelling.

---

## Capitalization

Use sentence case for headings.

Correct:

```markdown
## Basic greetings
```

Avoid:

```markdown
## BASIC GREETINGS
```

or

```markdown
## Basic Greetings
```

Component names may use Title Case.

Examples:

- Vocabulary Card
- Grammar Box
- Audio Button

---

## User Interface

Use short, consistent labels.

Preferred examples:

- Listen
- Next Lesson
- Previous Lesson
- Show Answer
- Check Answer
- Replay Audio

Avoid using different labels for identical actions.

---

## Technical Terms

Use these terms consistently.

| Preferred | Avoid |
|-----------|-------|
| Component | Widget |
| Layout | Template *(except `lesson-template.md`)* |
| Page | Screen |
| Dictionary Entry | Vocabulary Record |
| Grammar Reference | Grammar Wiki |

---

## Audio

Use:

**Text-to-Speech (TTS)**

After the first mention, **TTS** may be used.

For recorded pronunciations, use:

**Native Speaker Audio**

---

## Future Features

Use the official feature names.

- Progress Tracking
- Flashcards
- Search
- Grammar Reference
- Dictionary
- User Accounts
- Spaced Repetition

---

## File Naming

Documentation files should use lowercase filenames with hyphens.

Examples:

```
course-plan.md
lesson-template.md
style-guide.md
grammar-reference.md
```

Avoid spaces and mixed capitalization.

---

## Project Name

Always write the project name as:

**OpenTagalog**

Not:

- Open Tagalog
- Open-Tagalog
- Opentagalog
- opentagalog

The GitHub repository name may remain lowercase (`opentagalog`) where required by GitHub conventions.

---

## Consistency Before Preference

Consistency is more important than individual writing preference.

If a lesson, dictionary entry, grammar page, or documentation page introduces terminology that differs from the established project standards, update it to match the existing terminology unless there is a strong educational reason not to do so.

When in doubt, follow this Style Guide.
